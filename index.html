00 / BEFORE WE BEGIN

密码学并不是只有“加密”这一件事

想象你要给远方朋友寄一封秘密信：你要避免别人偷看、篡改、冒充，还得解决“双方怎么拥有同一把钥匙”。每一类密码工具只负责其中一部分。

01 · CONFIDENTIALITY让内容看不懂AES / SM4 / ChaCha20
真正加密大量数据
02 · KEY ESTABLISHMENT让双方得到钥匙ECDH / ML-KEM
在公开信道建立秘密
03 · AUTHENTICITY证明消息来自谁ECDSA / RSA-PSS / ML-DSA
签名与身份验证
04 · FINGERPRINT快速识别内容变化SHA-256 / SHA-3
固定长度内容指纹
先建立一个正确的大局观：HTTPS 里通常是“证书与签名认证身份 → 公钥机制建立共享密钥 → AES-GCM 或 ChaCha20-Poly1305 保护数据”。量子计算重点冲击公钥机制，并不意味着所有 AES 加密都会随之失效。

每章遵循四步：先说人话 → 看原理图 → 动手算一次 → 不看答案自己讲。文中的小数字只为教学，绝不能用于真实密码系统。

01 / SYMMETRIC ENCRYPTION

AES｜双方共用一把钥匙

要保护一份 10GB 的文件，怎样又快又可靠地把它变成只有持钥者才能读懂的数据？

▦
一句人话：AES 像一台有秘密设置的搅拌机。同一把密钥决定它怎样把每个 128 位数据块反复替换、打散、混合；知道密钥的人才可以按逆操作还原。

真正的 AES 并不是“异或一次”

AES 每次处理 128 bit = 16 Byte 的数据块，将它排成 4 × 4 的状态矩阵。AES-128、AES-192、AES-256 的密钥长度不同，对应分别执行 10 / 12 / 14 轮。输入还会先执行一次 AddRoundKey；最后一轮不做 MixColumns。

✓
量子影响：不会像 RSA 那样结构性失效

已知通用的 Grover 搜索在理想模型下可把 AES-256 密钥搜索的查询量级由 2²⁵⁶ 降至 2¹²⁸；真实量子电路和纠错开销非常巨大。

工程补充：AES 是分组密码；实际通信还需要正确的工作模式。AES-GCM 同时提供机密性与认证，必须妥善管理 nonce，不能随意复用同一密钥下的 nonce。

检查理解｜为什么知道 AES 算法设计也不能直接解密？

安全设计默认算法公开；秘密在高熵密钥中。攻击者即使知道 S-box、轮变换和实现流程，也应无法在可行成本内恢复密钥。实际系统也必须注意密钥泄露、侧信道和 nonce 复用等实现问题。

02 / ASYMMETRIC CRYPTOGRAPHY

RSA｜公钥公开，私钥为什么还安全？

你把锁的结构公开给所有人，为什么只有持有私钥的人能打开它？关键不是藏算法，而是某个逆向数学问题非常难。

pq
一句人话：把两个很大的质数相乘很容易，但别人只看到乘积，想反推出这两个质数，在经典计算下可能非常困难。RSA 的密钥关系利用了这种不对称性。
图解｜从两个质数生成一对密钥RSA 教学算例
质数 p = 5
质数 q = 11只有持钥方知道
→
n = pq = 55φ(n) = 4 × 10 = 40
→
公钥 (e,n) = (3,55)可以公开给任何人
私钥 d = 27 ，因为 3 × 27 = 81 ≡ 1 (mod 40)

“mod 40”就是除以 40 后看余数。私钥 d 与公钥 e 满足特殊的模运算关系，这使加密和解密可相互配合。

交互实验｜输入一个 0～54 的数字，亲眼看它被加密又解密可操作

明文 m7
公钥加密 c = m³ mod 5513
私钥解密 m = c²⁷ mod 557
这个例子极小，只是为了让你算得动。真实 RSA 使用大得多的整数，而且必须使用安全编码和填充，例如 RSA-OAEP；不能把这里的“裸 RSA”直接用于生产。

量子计算击中 RSA 的什么地方？

如果获得足够强大的纠错量子计算机，Shor 算法可以通过高效求解周期问题来分解大整数。RSA 依赖的计算困难性因此会受到根本威胁，区别于“穷举快了一点”。

!
量子影响：根本性威胁

传统 RSA 加密和 RSA-PSS 等 RSA 签名都依赖相关整数计算结构。拥有足够能力的量子攻击者可能恢复私钥，从而破坏保密性和签名真实性。

🗣 费曼复述

解释给朋友听：为什么“公开 RSA 公钥”不等于“把解密方法交出去”？量子计算又改变了哪一步？

检查理解｜假设两个质数只有 5、11，RSA 真的安全吗？

完全不安全。攻击者看到 n=55 就能立即分解成 5×11。RSA 的安全性依赖足够大的参数、正确的填充、密钥保护与实现；小数字只是一张帮助理解的草稿纸。

03 / ELLIPTIC-CURVE CRYPTOGRAPHY

ECC｜用“点的运算”代替大数分解

RSA 靠分解难题，ECC 则靠另一种难题：从曲线上的一个起点出发，可以高效算出终点，但别人很难倒推走了多少步。

∿
一句人话：假设你在一张特殊地图上按固定规则移动 7 次，很容易知道终点；别人知道起点和终点，却很难推算你究竟移动了多少次。ECC 的“移动”是严格定义的数学点加法，并不是沿曲线走路。

典型曲线方程可以写成 y² = x³ + ax + b。在密码学里常用的是有限域上的点，而不是连续的光滑曲线。点与点之间定义了特定的加法，反复相加写成 Q = kP，称作标量乘法。

图解｜有限域上的真实小曲线：y² = x³ + 2x + 2 (mod 17)可操作

每个蓝点都满足模 17 曲线方程；绿色点是基点 P=(5,1)，橙点是当前的 kP。

7

给定基点 P = (5,1)

(0, 6)

7P = Q

真正的难题：只公开 P 和 Q，怎样反推出 k？

2P = (6,3)
3P = (10,6)
7P = (0,6)

该教学曲线中基点 P 的阶是 19，19P 是无穷远点 O。真实曲线使用远大于此的群。

离散点才是正确的有限域图像。不要把 ECC 误解为连续几何曲线上的普通位移，也不要把点乘当作两个坐标相乘。
手算一次｜为什么 2P = (6,3)只需要看懂取余数
λ = (3·5² + 2)/(2·1) mod 17 = 13
x₃ = λ² − 2x₁ = 169 − 10 ≡ 6 (mod 17)
y₃ = λ(x₁ − x₃) − y₁ = 13(5 − 6) − 1 ≡ 3 (mod 17)

模运算里的“除以 2”，其实是乘以 2 的模逆元 9（2×9 mod 17 = 1）。这就是有限域运算和日常小数除法的不同。

!
量子影响：根本性威胁

ECC 的安全难题是椭圆曲线离散对数。Shor 算法也能够高效求解，因此 256 位 ECC 并不因为“密钥长度 256 位”就拥有 AES-256 式的抗量子安全性。

🗣 费曼复述

请解释 Q=kP 为什么“正向容易、逆向困难”，并说明 ECC 与 RSA 的困难问题有何不同。

检查理解｜ECC 能用来加密、签名和交换密钥吗？

ECC 是一类数学基础，不是一个独立的万能协议。基于它可以构造 ECDH 密钥协商、ECDSA 数字签名，也有椭圆曲线公钥加密方案。用途不同，安全目标也不同。

04 / KEY AGREEMENT

ECDH｜公开交流，怎么得到同一个秘密？

两个人从未见过面，通信还可能被旁听。他们怎样在不直接发送秘密密钥的情况下得到相同的共享秘密？

⇄
一句人话：Alice 私下选数字 a，Bob 私下选数字 b；两人都从公开的点 P 出发。Alice 公开 aP，Bob 公开 bP，然后分别使用自己的私有数字做一次点乘，最终都得到 abP。

实际协议还要把共享点通过 KDF 派生为会话密钥，并认证通信对象。ECDH 本身不能防止中间人分别和双方协商不同的密钥。
!
量子影响：Shor 可能从公开点恢复秘密标量

恢复出 a 或 b 就能重建共享秘密。这也是“先保存流量，未来再解密”（Harvest Now, Decrypt Later）的核心风险之一。

🗣 费曼复述

解释为什么 Alice 算 aB、Bob 算 bA 最终相同，但旁听者只有 P、A、B 却难以算出它们。

检查理解｜ECDH 已经保证会话密钥保密，还需要证书吗？

需要独立的身份认证。没有认证的 ECDH 易遭中间人攻击：攻击者分别与两端建立密钥，成为两个合法密钥交换的参与者。这与“被动旁听者无法求解”是两件不同的事。

05 / DIGITAL SIGNATURES

ECDSA｜数字签名不负责保密

如果你下载了一份固件，如何判断它确实由芯片厂商发布、而且下载过程中没有被替换？

✍
一句人话：只有厂商持有私钥，因此只有厂商能够生成可被相应公钥验证的签名。签名不把固件藏起来，而是让任何持有可信公钥的人检查“这份内容有没有被指定的私钥签过”。
图解｜签名与验签是两条不同的数据路径SoC Secure Boot 场景

算法名 ECDSA 中的 EC 仍然是椭圆曲线。它不是“用私钥把消息加密”，而是一种专门设计的签名数学构造。

甚至可以用刚才那条小曲线，算出一份签名

手算｜P=(5,1)、群阶 n=19、私钥 d=7、摘要 z=9极小教学参数
临时随机数 k = 3R=3P=(10,6)
r = x(R) mod 19r = 10
s = k⁻¹(z + rd) mod 19s = 1
签名 (r,s) = (10,1)；公钥 Q = dP = (0,6)
验签：w=s⁻¹=1, u₁=zw=9, u₂=rw=10
u₁P + u₂Q = 9P + 10(7P) = 79P = 3P = (10,6)

验签算出的点的 x 坐标模 19 后仍是 10，等于 r，验证通过。真实 ECDSA 还有签名参数合法性检查、摘要处理、抗侧信道实现等要求。

关键安全边界：ECDSA 里的签名随机数 k 是极其敏感的。若重复使用或泄漏 k，可能暴露长期私钥。安全实现通常使用严格受控的随机数产生方式或适用的确定性签名流程。
!
量子影响：Shor 攻击 ECC 离散对数基础

量子攻击者一旦能从公钥恢复签名私钥，就可能伪造合法固件签名。AES 加密固件不自动解决签名身份可信问题。

🗣 费曼复述

假如某个固件完全没有加密，但 ECDSA 验签通过，它到底保护了什么？又没有保护什么？

检查理解｜RSA-PSS、ECDSA、ML-DSA 的共同任务是什么？

共同任务是数字签名：由私钥生成可公开验证的证明，验证消息内容与签名者密钥的关系。RSA-PSS 使用 RSA 及安全随机化填充，ECDSA 使用椭圆曲线，ML-DSA 使用模格困难问题；它们不是同一套数学运算。

06 / CRYPTOGRAPHIC HASHING

SHA-256｜不是加密，而是给内容做指纹

为什么一个上 GB 的文件，最后能被压缩成固定 256 位的摘要？摘要变了意味着什么？

#
一句人话：SHA-256 像一台特殊的“压印机”：扔进去一段任意长度的消息，就得到 256 位结果。改变一点点输入，输出通常就会大幅变化；拿着输出不能像解密那样还原原文。
动手看｜输入只变化一个字符，摘要就面目全非在本地实际计算 SHA-256
当前输入的 SHA-256
ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad
对照：字符串 abd
a52d159f262b2c6ddb724a61840befc36eb30c88877a4030b65cbe86298449c9

输入长度：3 字符 / 3 字节 · 输出始终 64 个十六进制字符，即 256 位。

这里计算的是标准 SHA-256 摘要。它不是“通过 SHA-256 加密一段消息”；哈希没有专门的解密密钥或解密操作。

三件容易被混在一起的事

原像问题

给定摘要 H(m)，找到一条能产生该摘要的消息 m。

第二原像

已知消息 m，再找一条不同消息 m′，却有同样的摘要。

碰撞

自由挑选两条不同消息 m₁、m₂，让它们的摘要一致。

对理想的 256 位哈希，经典原像搜索约需要 2²⁵⁶ 次尝试，经典碰撞搜索受生日界影响约需 2¹²⁸ 次。量子算法会改变这些通用攻击的查询复杂度，但不同攻击目标不能混为一谈。

≈
量子影响：存在通用量子加速，并非哈希“可逆”

Grover 可在理想模型下把原像搜索查询量级降至约 2¹²⁸。对于理想哈希碰撞，也存在不同于 Grover 的量子算法；安全结论需要按具体用途和模型分析。

工程提醒：单独把“文件 + SHA-256 摘要”发给别人不能防伪，因为攻击者可以同时替换文件和摘要。要认证来源，需要可信签名或带密钥的 MAC。

🗣 费曼复述

向一个从未学过密码学的人解释：SHA-256 和 AES 的区别是什么？为什么两个不同文件可能有相同的摘要，却依旧被认为安全？

检查理解｜有人只给你文件和 SHA-256 摘要，就能证明文件没被攻击者改过吗？

不能独立证明。只有当“正确摘要”来自可信渠道时，哈希校验才有意义；否则攻击者能够把恶意文件和它对应的摘要一起交给你。

07 / MESSAGE AUTHENTICATION

HMAC｜给内容指纹加上一把秘密钥匙

哈希可以发现内容变化，但谁都能算哈希。怎样让只有知道共享密钥的双方，才能算出正确的认证标签？

⌘
一句人话：普通 SHA-256 像一台公共指纹机，所有人都可以对任何文件做指纹；HMAC 在计算过程中还混入双方共享的秘密，因此攻击者即使看见消息和标签，也无法随意为修改后的内容生成有效标签。

修改内容但不知道 K，难以产生能通过验证的新标签。

这里的 || 表示拼接，ipad / opad 是定义好的内部/外部填充值，H 通常是 SHA-256。HMAC 并不是简单的 H(K || M)。

✓
量子影响：与 RSA / ECC 不同

HMAC 属于对称密钥认证机制。量子威胁取决于密钥强度、底层哈希和具体安全性质，不存在直接套用 Shor 算法恢复私钥的情形。

HMAC 的验证者也持有秘密密钥，因此不具备普通数字签名的“任何人只凭公钥就可验证”的性质。两者不能互相替代。

🗣 费曼复述

为什么 HTTPS 和 SoC 协议里既需要哈希，也经常需要 HMAC 或 AEAD？HMAC 与数字签名的不同又是什么？

检查理解｜为什么不用 HMAC 替代所有公钥签名？

因为 HMAC 需要验签双方共享密钥；知道密钥的一方也可以生成标签。软件发行、证书等场景希望验证者只需持有公开的公钥，而不能据此伪造开发商签名，所以需要数字签名。

08 / QUANTUM ALGORITHM

Shor｜为什么量子计算能威胁 RSA 和 ECC？

量子计算不是“所有答案一起算出来、直接读出来”。Shor 的核心是把某些问题转化为寻找周期，再用量子干涉高效提取周期信息。

ψ
一句人话：如果一个数字规律每隔几步就重复，找到它的周期可能会帮助你分解一个大数。Shor 的量子部分擅长提取这种周期；经典后处理再把周期转化成因数。

RSA 为什么被打中？

大整数分解可归约到相关的周期寻找问题。Shor 可以利用这种数学结构。

ECC 为什么也被打中？

椭圆曲线离散对数属于可用量子算法高效解决的群结构问题，不必先做整数分解。

!
关键前提：足够强的容错量子计算机

理论上的高效算法不等于今天的量子设备已经实用破解 RSA-2048 或 P-256。逻辑量子位数量、纠错、门深度和运行可靠性都是巨大门槛。

检查理解｜能分解 15，为什么不代表能分解 RSA-2048？

15 只有 4 位，经典计算也能瞬间分解。RSA-2048 包含 2048 位模数，需要的大规模可靠量子计算、容错编码和量子门数量与玩具例子完全不同。算法的渐近优势不意味着当前硬件成熟。

10 / POST-QUANTUM · KEM

ML-KEM｜换一道量子计算还不擅长的难题

RSA 和 ECDH 都依赖 Shor 可以高效攻击的数学结构，那能否用另一类数学问题建立共享密钥？

▤
一句人话：攻击者面对的不再是“给我一个大乘积、让我找回因数”，而是“给我很多被小误差扰动的高维数学关系、让我恢复其中藏着的秘密”。这就是格密码中 Learning With Errors 思路的核心直觉。

为什么“一点点噪声”能改变求解难度？

b = As + e (mod 17)

攻击者知道 A 和 b，却不知道 e。如果错误地假设没有误差，按精确方程反推出的 (8,7) 与真正的 (3,2) 完全不同。

真实 ML-KEM 基于 Module-LWE，涉及高维多项式、具体参数、密钥封装与验证机制；这个 2×2 方程只解释“误差让逆推困难”的来源，完全不具备实际安全性。

ML-KEM 实际上是怎样给双方建立秘密的？

发布 pk
私钥 sk 留在本地
→公开的 pk

←密文 ct
Alice · 发起方使用 Bob 公钥 pk
Encaps(pk)
得到 ct 和共享秘密 K
Bob 使用 Decaps(sk, ct) → 得到同一个 K

随后双方使用 KDF 派生应用密钥，再通过 AES-GCM 等机制保护大量数据。

KEM（密钥封装）与 ECDH（密钥协商）的交互方式不同：ML-KEM 一方生成密钥对，另一方用公钥封装共享秘密；它不是“对原始文件进行 ML-KEM 加密”。

✓
抗量子性：基于目前没有已知高效量子算法的困难问题

NIST FIPS 203（2024）标准化了 ML-KEM-512、ML-KEM-768 和 ML-KEM-1024。它们是不同安全参数集，不是“密钥一定只有 512 / 768 / 1024 位”。

🗣 费曼复述

解释：格密码为何“允许合法方恢复秘密，却让攻击者面对难以恢复的扰动关系”？ML-KEM 到底建立了什么，而不是加密了什么？

检查理解｜ML-KEM 已经替换 ECDH，是不是证书认证也自然抗量子了？

不是。ML-KEM 解决共享密钥建立问题；证书里的传统 ECDSA 或 RSA 签名如果不迁移，身份认证仍可能受量子攻击。协议要同时考虑密钥建立与认证。

11 / POST-QUANTUM · DIGITAL SIGNATURE

ML-DSA｜后量子时代的“电子公章”

密钥协商升级后，软件签名、固件验签、证书颁发还需要一套能在未来量子威胁下继续使用的数字签名。

✦
一句人话：ML-DSA 与 ECDSA 做的是同一份工作：私钥持有者为消息签名，其他人用公开的公钥验签。不同之处是它背后使用模格问题，而不是椭圆曲线离散对数。

真实 ML-DSA 会构造与公钥数学关系相关的承诺、挑战和响应，不能只写成“哈希后私钥加密”。

如果固件内容发生变化，原先的签名通常无法再通过验证。

为什么不能直接用 ML-KEM 生成签名？

两者虽然都属于模格密码，但提供的安全功能不同。ML-KEM 是 Key Encapsulation Mechanism，旨在让双方获得共享秘密；ML-DSA 是 Digital Signature Algorithm，旨在生成可公开验证的签名。数学构造、输出和安全定义均不同。

ML-DSA-87数字签名更高安全强度，尺寸/运算开销随之增加

44 / 65 / 87 是参数集命名，不是“44 位、65 位、87 位的签名”。

✓
抗量子性：用新的困难问题建立签名安全基础

NIST FIPS 204（2024）已正式标准化 ML-DSA。仍需考虑实现的随机性、旁路泄漏、故障注入、签名大小和长期密钥保护。

有人说“我们已经把 ECDH 换成 ML-KEM，所以固件签名也安全了”。请找出这个说法的漏洞。

检查理解｜ML-DSA 的签名为什么可以被公开验证？

签名设计提供与私钥持有者相关的公开可验证数学关系；验证者只需要可信公钥、消息和签名，就可以检查对应关系。签名不应泄露用于伪造后续签名的秘密。

12 / POST-QUANTUM · HASH-BASED SIGNATURE

SLH-DSA｜让哈希树承担签名的信任链

除了模格密码，还能不能构造抗量子数字签名？答案是可以借助哈希函数与树形认证结构，但要付出不同的签名尺寸和速度代价。

♧
一句人话：想象你有一棵由哈希值构成的树。根值事先被信任；签名提供必要的分支信息，验证者便能沿着树向上重建根，证明某个一次性签名公钥被包含在可信结构里。
图解｜点击叶子，看看验证时需要哪些旁支哈希Merkle 树直觉模型

验证 L1 时，需要它的同层兄弟 L0 的哈希，以及上一层另一分支的哈希。沿途逐层合并，直到与可信根比较。

这是四叶 Merkle 树的教学模型。真正的 SLH-DSA 使用更复杂的无状态哈希签名体系，包括 WOTS+、FORS、多层树等，不是简单“把文件 SHA-256 几次”。

优点

安全假设建立在适当的哈希函数性质上，与格密码路线具有不同的数学依赖。

代价

通常需要较大的签名和更多哈希计算，工程中要权衡带宽、存储空间与验签性能。

✓
抗量子性：哈希签名路线

NIST FIPS 205（2024）标准化 SLH-DSA，基于 SPHINCS+。它是无状态方案，不要求签名设备像传统状态型一次性签名体系那样安全保存已用过的叶子索引。

🗣 费曼复述

向同事解释：Merkle 树为什么只用少量“兄弟哈希”就能证明某个叶子属于可信根？以及它为什么不等于一个完整数字签名算法？

检查理解｜为什么 SLH-DSA 和 ML-DSA 可以同时被标准化？

它们提供同一种数字签名功能，却基于不同的数学与工程权衡。不同路线有利于多样化安全假设与部署选择；不是一种算法“万能”，另一种必然多余。
